# 功能架构定义

## 产品架构概览

### 架构原则
- **一个软件，两种模式**：统一的入口，侧边栏切换
- **共享组件，独立功能**：共享AI助手、侧边栏等组件，功能完全独立
- **模式特定交互**：模式A一键操作，模式B对话式AI

---

## 页面结构

```
index.html (商家类型选择)
  ├─ mode-a.html (模式A：AI智能铺货管家)
  │   ├─ selection-a.html (一键选品)
  │   ├─ supply-a.html (一键货源)
  │   ├─ optimize-a.html (一键优化)
  │   └─ maintain-a.html (一键全店维护)
  │
  ├─ mode-b.html (模式B：AI深度运营分析师)
  │   ├─ tracking-b.html (爆品追踪)
  │   ├─ analysis-b.html (竞品分析)
  │   └─ diagnosis-b.html (六维诊断)
  │
  └─ assistant.html (AI助手)
```

---

## 页面功能定义

### 1. index.html - 商家类型选择页

#### 页面目的
- 帮助商家选择适合的产品模式
- 展示两种模式的对比
- 引导商家选择正确的模式

#### 页面内容
- **商家类型选择**：
  - 类型1：无货源/店群铺货型 → 选择模式A
  - 类型2：精品/品牌型 → 选择模式B
  - 类型3：中间型（"锅店"型）→ 可选择模式A+B组合

- **模式对比**：
  - 模式A：一键操作，自动化，追求效率、规模
  - 模式B：深度分析，对话式AI，追求深度、精准

#### 交互逻辑
- 点击"选择模式A" → 跳转到 mode-a.html
- 点击"选择模式B" → 跳转到 mode-b.html
- 点击"了解更多" → 显示详细介绍

---

### 2. mode-a.html - 模式A主界面

#### 页面目的
- 模式A（AI智能铺货管家）的主界面
- 提供一键操作的快捷入口
- 显示今日数据概览

#### 页面内容
- **快捷操作**：
  1. 一键选品
  2. 一键货源
  3. 一键优化
  4. 一键全店维护

- **今日数据概览**：
  - 今日选品（已选中）
  - 已对接货源（可下单）
  - 今日优化（已优化）
  - 今日增收（环比）

- **推荐产品列表**：
  - 今日推荐的产品
  - 一键选中、查看详情

- **AI助手（铺货助手）**：
  - 对话式界面
  - 提供铺货建议

#### 交互逻辑
- 点击快捷操作卡片 → 跳转到对应功能页
- 点击"一键选中" → 添加到已选列表
- 点击"查看详情" → 显示产品详情弹窗
- AI助手对话 → 对话式交互

---

### 3. mode-b.html - 模式B主界面

#### 页面目的
- 模式B（AI深度运营分析师）的主界面
- 提供深度分析功能的入口
- 显示分析能力概览

#### 页面内容
- **核心能力**：
  1. 爆品追踪与归因
  2. 竞品复刻与优化
  3. 六维象限诊断

- **分析能力概览**：
  - 今日追踪的商品
  - 今日分析的竞品
  - 今日诊断的店铺

- **AI助手（运营分析师）**：
  - 对话式界面
  - 提供分析建议

#### 交互逻辑
- 点击核心能力卡片 → 跳转到对应功能页
- AI助手对话 → 对话式交互

---

### 4. selection-a.html - 一键选品（模式A）

#### 页面目的
- 批量选择热品，一键上架

#### 页面内容
- **授权店铺**（首次使用）：
  - 显示授权按钮
  - 授权成功后显示店铺信息

- **商品匹配结果**：
  - 匹配的产品列表（商品名称、价格、爆品分数）
  - 标注类型（长周期、短周期、趋势品）
  - 显示"已选"状态

- **批量操作**：
  - 一键全选
  - 取消全选
  - 一键上架

- **数据统计**：
  - 已选商品数量
  - 预计上架时间

#### 交互逻辑
- 点击"授权店铺" → 调用授权API → 显示店铺信息
- 系统自动匹配 → 显示匹配结果
- 点击"一键全选" → 所有商品变为"已选"
- 点击"一键上架" → 批量上架 → 显示成功数量

---

### 5. supply-a.html - 一键货源（模式A）

#### 页面目的
- 对接1688货源库，找货、比价、自动下单

#### 页面内容
- **已选商品列表**：
  - 显示已选商品
  - 显示建议售价

- **货源匹配结果**：
  - 1688货源列表（平台、价格、评分、时效）
  - 价格对比（1688价格 vs 建议售价）
  - 利润计算

- **供应商筛选**：
  - 按评分筛选
  - 按时效筛选
  - 过滤劣质供应商

- **批量操作**：
  - 选择最佳供应商
  - 一键下单

#### 交互逻辑
- 页面加载 → 显示已选商品列表
- 点击"匹配货源" → 调用API → 显示货源列表
- 点击"选择供应商" → 标记为已选
- 点击"一键下单" → 批量下单 → 显示成功数量

---

### 6. optimize-a.html - 一键优化（模式A）

#### 页面目的
- 批量优化标题、主图、详情页

#### 页面内容
- **待优化商品列表**：
  - 显示待优化商品

- **优化方案**：
  - AI优化的标题（原版 vs 优化版）
  - AI优化的主图（原版 vs 优化版，AIGC生成）
  - AI优化的详情页（原版 vs 优化版）

- **优化对比**：
  - 并排显示原版和优化版
  - 高亮显示差异

- **批量操作**：
  - 一键应用优化
  - 批量应用优化

#### 交互逻辑
- 页面加载 → 显示待优化商品列表
- 点击"生成优化方案" → 调用AI → 显示优化结果
- 点击"查看对比" → 显示原版 vs 优化版
- 点击"一键应用优化" → 应用优化 → 显示成功数量

---

### 7. maintain-a.html - 一键全店维护（模式A）

#### 页面目的
- 全店标题优化、直通车调价、自动维护

#### 页面内容
- **全店诊断结果**：
  - 全店商品列表
  - 显示需要维护的商品
  - 按增收潜力排序（优先级）

- **维护计划**：
  - 标题优化机会
  - 价格调整建议
  - 投流优化建议

- **预期效果**：
  - 预计增收金额
  - 预计增收比例

- **批量操作**：
  - 一键执行维护
  - 定期自动维护

#### 交互逻辑
- 页面加载 → 调用诊断API → 显示诊断结果
- 显示维护计划（按优先级排序）
- 点击"一键执行维护" → 执行维护 → 显示成功数量
- 选择"定期自动维护" → 设置维护周期

---

### 8. tracking-b.html - 爆品追踪（模式B）

#### 页面目的
- 追踪爆品流量和销量变化，归因分析，给出建议

#### 页面内容
- **爆品信息**：
  - 商品基本信息
  - 追踪状态

- **流量趋势图**：
  - K线图形式显示流量变化
  - 关键时间点标注

- **销量变化曲线**：
  - 显示销量变化趋势
  - 关键时间点标注

- **关键动作时间线**：
  - 调价时间点
  - 换图时间点
  - 达人合作时间点
  - 关键动作对数据的影响

- **归因分析**：
  - 分析哪个动作导致了流量/销量变化
  - 讲清楚"为什么"

- **跟进建议**：
  - 是否跟进
  - 如何跟进
  - 预期效果

- **AI助手对话**：
  - 对话式交互
  - 提供追踪建议

#### 交互逻辑（对话式）
- 用户输入："我要追踪凉鞋这个爆品的趋势"
- AI：显示商品信息输入框
- 用户输入：商品链接或名称
- AI：调用追踪API → 生成分析报告
- AI：显示流量趋势图、销量变化曲线、关键动作时间线
- AI：显示归因分析
- AI：显示跟进建议

---

### 9. analysis-b.html - 竞品分析（模式B）

#### 页面目的
- 深度分析竞品，讲清楚"好在哪里"，提供优化方向

#### 页面内容
- **竞品信息**：
  - 商品基本信息
  - 分析状态

- **标题分析**：
  - 词汇结构分析
  - 关键词布局分析
  - 标题优化建议

- **主图分析**：
  - 构图分析
  - 元素分析
  - 文案风格分析
  - 主图优化建议

- **价格分析**：
  - 价格定位分析
  - SKU策略分析
  - 定价优化建议

- **详情页分析**：
  - 卖点提炼分析
  - 信息架构分析
  - 详情页优化建议

- **成功要素总结**：
  - 讲清楚"好在哪里"
  - 识别成功的要素

- **优化方向**：
  - 基于分析，提供优化方向

- **AIGC生成**（可选）：
  - 生成符合"爆款风格"的新主图
  - 生成4套视觉方案
  - 用户选择最佳方案

- **AI助手对话**：
  - 对话式交互
  - 提供分析建议

#### 交互逻辑（对话式）
- 用户输入："帮我分析这个竞品为什么卖得好"
- AI：显示商品链接输入框
- 用户输入：竞品链接
- AI：调用分析API → 深度分析
- AI：显示标题分析、主图分析、价格分析、详情页分析
- AI：显示成功要素总结
- AI：显示优化方向
- AI：询问是否需要AIGC生成新主图
- 用户：选择需要
- AI：生成4套视觉方案 → 用户选择最佳方案

---

### 10. diagnosis-b.html - 六维诊断（模式B）

#### 页面目的
- 六维诊断店铺运营状况，对比自身与竞品，识别优势和短板

#### 页面内容
- **店铺信息**：
  - 店铺基本信息
  - 诊断状态

- **六维诊断结果**：
  1. 投流：得分、趋势
  2. 内容：得分、趋势
  3. 体验：得分、趋势
  4. 服务：得分、趋势
  5. 产品：得分、趋势
  6. 定价：得分、趋势

- **对比分析**（自身 vs 竞品）：
  - 每个维度的对比
  - 识别优势和短板

- **ROI来源分析**：
  - "高ROI的钱是从哪赚来的"
  - 主要ROI来源识别

- **改进建议**：
  - 基于诊断结果，提供改进建议

- **AI助手对话**：
  - 对话式交互
  - 提供诊断建议

#### 交互逻辑（对话式）
- 用户输入："帮我诊断一下我店铺的运营状况"
- AI：显示店铺信息输入框或维度选择
- 用户输入：店铺信息或选择诊断维度
- AI：调用诊断API → 六维诊断
- AI：显示六维诊断结果（得分、趋势）
- AI：显示对比分析（自身 vs 竞品）
- AI：显示ROI来源分析
- AI：显示改进建议

---

### 11. assistant.html - AI助手

#### 页面目的
- 统一的AI助手入口
- 根据模式展现不同角色

#### 页面内容
- **AI助手角色**：
  - 模式A：铺货助手（Picking Assistant）
  - 模式B：运营分析师（Operations Analyst）

- **对话界面**：
  - 对话历史记录
  - 输入框
  - 发送按钮

- **快捷操作**（模式A）：
  - 一键选品
  - 一键货源
  - 一键优化
  - 一键维护

- **快捷查询**（模式B）：
  - 爆品追踪
  - 竞品分析
  - 六维诊断

#### 交互逻辑
- 页面加载 → 根据当前模式显示对应角色
- 用户输入 → AI生成回复
- 模式A：铺货助手提供自动化建议
- 模式B：运营分析师提供分析建议

## 共享组件

### 1. 侧边栏
- **品牌区**：显示品牌名称和标语
- **导航菜单**：
  - 商家类型
  - 模式A（当前模式则高亮）
  - 模式B（当前模式则高亮）
  - AI助手
- **底部信息**：当前模式、版本号

### 2. 顶部栏
- **面包屑导航**：显示当前页面路径
- **页面标题**：当前页面标题
- **模式切换**：模式A ↔ 模式B切换
- **状态显示**：系统运行状态

### 3. AI助手
- **对话界面**：消息列表、输入框、发送按钮
- **角色切换**：根据模式自动切换角色
- **快捷操作**：根据模式显示对应快捷操作

## 导航逻辑

### 页面跳转规则

```
index.html
  ├─ 点击"选择模式A" → mode-a.html
  └─ 点击"选择模式B" → mode-b.html

  ├─ 点击"一键货源" → supply-a.html

  └─ 点击"一键全店维护" → maintain-a.html

mode-b.html

  └─ 点击"AI助手" → assistant.html
```

- maintain-a.html 返回 mode-a.html
- tracking-b.html 返回 mode-b.html
- analysis-b.html 返回 mode-b.html

- 点击"模式B" → 跳转到 mode-b.html

## 状态管理

### 模式状态
- 当前模式：A或B
- 根据URL自动判断（mode-a.html = 模式A，mode-b.html = 模式B）

### 授权状态
- 是否已授权店铺
- 已授权店铺列表

### 选择状态
- 已选商品列表
- 选择数量统计

### 追踪状态
- 追踪的商品列表
- 追踪状态（进行中、已完成）

### 诊断状态
- 诊断的店铺列表
- 诊断状态（进行中、已完成）
