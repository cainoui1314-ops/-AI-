# 客户画像与需求分析

## 三类客户画像

### 客户类型1：无货源/店群铺货型

#### 典型代表
- "一个人开100家店"的商家

#### 核心特征
- **规模**：一人管理数十上百家店
- **运营**：运营粗糙，客单价低
- **策略**：追求"铺满"商品，以量取胜

#### 核心诉求
- **关键词**："一键铺满"
- **不关心**：分析、洞察、决策支持
- **只要**：AI能自动、高效地替他将热品铺满店铺
- **目标**：绕过平台限制，快速铺满

#### 付费动机
- **核心动机**：**增收**
- 能用工具铺更多商品，赚到更多钱
- 为"增收"付费，而非为"分析"付费

#### 典型场景
- 商家授权店铺 → 系统自动匹配爆品 → 批量选择 → 自动上架
- 全店商品标题优化 → 直通车调价 → 自动维护
- 对接1688货源 → 自动下单 → 快速发货

#### 决策因素
- **效率**：铺货速度有多快？
- **规模**：能铺多少家店？多少商品？
- **增收**：能增加多少收入？
- **价格**：收费标准是多少？

---

### 客户类型2：精品/品牌型

#### 典型代表
- 宝玉
- 马克华菲

#### 核心特征
- **货源**：自有货源或深度供应链
- **店铺**：店铺少而精
- **运营**：日消耗高，有专业运营团队
- **战略**：追求精细化运营，品牌化

#### 核心诉求
- **关键词**："深度分析，指导决策"
- **需要**：理解市场、竞品和自己
- **指导**：投流、达人合作、视觉优化等精细运营
- **目标**：提升ROI，降低风险

#### 付费动机
- **核心动机**：**深度洞察**
- 能用工具发现关键机会、规避风险、提升ROI
- 为深度洞察付费

#### 典型场景
- 追踪爆品 → 分析归因 → 给出跟进建议
- 分析竞品 → 深度拆解 → 给出优化方向
- 店铺诊断 → 六维分析 → 发现优势和短板

#### 决策因素
- **深度**：分析有多深？
- **精准**：建议有多准？
- **可决策**：能否直接指导决策？
- **价值**：能否提升ROI？

---

### 客户类型3：中间型（"锅店"型）

#### 典型代表
- 全店靠少数爆品驱动的店铺

#### 核心特征
- **策略**：全店仅靠3-10个爆品驱动
- **定位**：介于铺货与精品之间
- **风险**：爆品衰退即店铺衰退

#### 核心诉求
- **关键词**："组合需求"
- **需要**：爆品追踪维护"命脉"
- **也需要**：一定的新品测试能力

#### 付费动机
- **核心动机**：**爆品维护+潜力挖掘**
- 维护现有爆品不衰退
- 挖掘新的潜力爆品
- 为"组合功能"付费

#### 典型场景
- 爆品追踪 → 归因分析 → 维护策略
- 新品测试 → 潜力评估 → 补充爆品

#### 决策因素
- **爆品维护**：能否维护好现有爆品？
- **潜力挖掘**：能否找到新的潜力品？
- **组合性价比**：爆品维护+潜力挖掘的组合价值

## 客户对比分析

### 维度对比表

| 维度 | 铺货型 | 精品型 | 中间型 |
|------|--------|--------|--------|
| **店铺数量** | 数十上百家 | 少而精 | 少 |
| **运营风格** | 粗糙，自动化 | 精细，专业 | 中等 |
| **客单价** | 低 | 高 | 中等 |
| **日消耗** | 低 | 高 | 中等 |
| **核心诉求** | 一键铺满 | 深度分析 | 爆品维护 |
| **付费动机** | 增收 | 深度洞察 | 组合功能 |
| **决策因素** | 效率、规模、增收 | 深度、精准、可决策 | 爆品维护+潜力挖掘 |
| **产品方案** | 模式A | 模式B | 模式A+B组合 |

### 核心差异

#### 铺货型 vs 精品型

| 方面 | 铺货型 | 精品型 |
|------|--------|--------|
| **运营理念** | 以量取胜 | 以质取胜 |
| **决策方式** | 快速决策 | 深度分析 |
| **价值诉求** | 效率、规模 | 深度、洞察 |
| **交互模式** | 一键操作 | 对话式AI |
| **收费模式** | 低价按量 | 高阶按模块 |
| **适合功能** | 自动化批量操作 | 深度归因分析 |

#### 中间型的特殊性
- 介于两者之间，需要"组合需求"
- 既要维护现有爆品（精品型需求）
- 又要挖掘新爆品（铺货型需求）
- 可以从模式A和B中选择合适功能组合

## 需求总结

### 模式A适合的客户
✅ **铺货型商家**
- 一个人管理数十上百家店
- 追求效率、规模、增收
- 需要自动化、批量操作

✅ **中间型商家（部分需求）**
- 需要新品测试和挖掘
- 需要批量操作能力

### 模式B适合的客户
✅ **精品/品牌型商家**
- 自有货源或深度供应链
- 店铺少而精
- 追求深度分析、决策支持

✅ **中间型商家（部分需求）**
- 需要爆品追踪维护
- 需要归因分析和诊断

### 中间型商家的选择
- 可以同时使用模式A和模式B
- 从模式A选择：一键选品、一键货源
- 从模式B选择：爆品追踪、归因分析
- 组合使用，满足"组合需求"

## 客户画像验证

### 验证方法
- 与一线商家（如宝玉的运营）深度沟通
- 验证产品假设是否准确
- 挖掘更多细分需求

### 关键问题
1. 您的店铺数量是多少？
2. 您的运营团队规模如何？
3. 您最关心的问题是什么？
4. 您愿意为这个功能付多少钱？
5. 如果这个功能能帮您增收XX元，您愿意付XX元吗？

### 持续迭代
- 根据实际商家反馈不断调整画像
- 发现新的细分需求
- 优化产品设计
