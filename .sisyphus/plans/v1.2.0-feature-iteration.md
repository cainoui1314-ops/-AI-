# 悦己AI v1.2.0 — 功能迭代方案

## TL;DR

> **核心目标**：从 MarketMind AI 更名为悦己AI，新增登录注册系统、抖店绑定、Skills人设系统、YUE自有模型体系、智能调度，建立完整的用户认证+商业化闭环。
>
> **品牌变更**：MarketMind AI → 悦己AI，品牌色改为高级黑色系
>
> **预计工作量**：Large
> **并行执行**：YES - 4个Wave
> **关键路径**：品牌替换 → 类型定义 → 认证系统 → 设置页改造 → Skills人设 → 模型体系 → 智能调度

---

## Context

### 原始需求
用户要求在 v1.2.0 版本中：
1. 将产品从 MarketMind AI 改名为悦己AI，品牌色换高级黑色
2. 设置页通用板块添加抖店绑定信息
3. 新增登录/注册页面（含抖店快捷登录）
4. Skills 加入 AI 人设系统（每个Skill 2-3个预设人设 + 1个自定义）
5. 对话框模型改为自有 YUE 系列（背后可接任意外部API）
6. 付费版核心卖点：智能体自动选择（YUE Auto）

### 用户确认的关键决策
- 抖店绑定：真实 OAuth 对接
- 登录方式：手机号 + 密码简单登录
- 自有模型：先定义接口格式，后端后面对接
- Skills人设：每个Skill 2-3个预设 + 1个自定义
- 计费模式：免费版按次数，付费版按Token
- 品牌色：高级黑色系（纯黑 + 深灰 + 蓝色交互点缀）
- 智能体自动选择：前端实现（关键词/意图匹配）
- Logo：文字Logo（纯文字"悦己AI"，类似 Notion/Linear 风格）
- 一键上架人设改为：精品上架 vs 批量铺货
- 目标群体：有货源商家

### 免费版 vs 付费版能力边界

| 能力 | 免费版 | 专业版 ¥29/月 | 企业版 ¥99/月 |
|------|--------|--------------|--------------|
| 基础对话 | ✅ 100次/月 | ✅ 按Token | ✅ 按Token |
| 全部6个Skills | ✅ | ✅ | ✅ |
| 默认人设 | ✅ | ✅ | ✅ |
| 人设切换 | ❌ 只有默认 | ✅ 全部 | ✅ 全部 |
| 自定义人设 | ❌ | ✅ | ✅ |
| YUE Pro | ✅ | ✅ | ✅ |
| YUE Fast | ✅ | ✅ | ✅ |
| YUE Ultra | ❌ | ✅ | ✅ |
| YUE Auto（智能调度） | ❌ | ✅ | ✅ |
| 抖店数据同步 | ✅ | ✅ | ✅ |
| Token包购买 | ❌ | ✅ | ✅ |
| 批量铺货模式 | ❌ | ✅ | ✅ |

## Work Objectives

### Core Objective
将悦己AI从纯前端Demo升级为具备完整用户认证、抖店绑定、模型体系、人设系统、双轨计费的准生产级产品。

### Concrete Deliverables
- LoginView.vue（登录+注册页面）
- AuthCallbackView.vue（抖店OAuth回调）
- auth.ts Store（认证状态管理）
- useApi.ts（统一API调用封装）
- 改造后的 SettingsView（抖店绑定 + 双轨额度）
- 改造后的 SkillsView（人设选择器）
- 改造后的 ChatInput（YUE模型选择器 + Token展示）
- 全局品牌替换（MarketMind → 悦己AI）
- 品牌色体系升级（黑色系）
- 文字Logo组件

### Definition of Done
- [ ] `vite build` 通过 0 errors
- [ ] 所有品牌文案从 MarketMind 替换为悦己AI
- [ ] 登录/注册页面可渲染，tab切换正常
- [ ] Router auth guard 未登录跳转 /login
- [ ] SettingsView 通用Tab显示抖店绑定信息
- [ ] SkillsView 显示人设选择器
- [ ] ChatInput 显示 YUE 系列模型
- [ ] 品牌色替换为黑色系

### Must Have
- 悦己AI品牌替换（文案 + 色彩 + Logo）
- 登录/注册页面（手机号+密码）
- 抖店绑定UI（含OAuth回调页）
- Skills人设系统（2预设+1自定义 per Skill）
- YUE模型体系（Pro/Fast/Ultra/Auto）
- 双轨计费UI（免费按次/付费按Token）
- Router auth guard
- auth.ts Store
- useApi.ts 封装

### Must NOT Have (Guardrails)
- 不实现真实的短信验证码服务（只用密码登录）
- 不实现真实的抖音OAuth对接（先定义接口格式，UI流程走通）
- 不实现真实的支付系统（Token购买只做UI展示）
- 不在后端做智能调度逻辑（前端关键词匹配）
- 不改动现有的对话核心逻辑（ChatMessages/ProductPanel只做微调）
- 不添加代码注释
- 不引入新的第三方UI库
